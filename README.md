# ThaiAI

Client-first, serverless, provider-agnostic AI workspace. See
`ThaiAI_Architecture.md` for the full architecture and design tokens.

## Setup

This scaffold was generated by hand (the build environment that produced it
has no network access, so `create-next-app`/`npm install` could not be run
here) but mirrors exactly what `create-next-app` (App Router, TypeScript,
Tailwind CSS, ESLint) would produce. To get it running:

```bash
npm install
npm run dev
```

Then open http://localhost:3000.

## Status — Phase 2 complete (items 1–9)

Item 1 (project setup) — done, see git history / original notes below.

Items 2–9 — done:
- **item 3 `core/storage`**: real Dexie/IndexedDB schema (`conversations`,
  `messages`, `projects`, `files`, `settings` tables) with full CRUD
  (`src/core/storage/*`), and `core/files` OPFS wrapper for file bytes
  (`src/core/files/opfs.ts`). Conversations, projects, files, and settings
  all persist across reloads now instead of resetting to `MOCK_*` arrays.
- **item 4 `core/parsers`**: real `FileParser` implementations for TXT, MD,
  JSON, CSV, HTML, CSS, XML, YAML, SQL, and JS/TS/JSX/TSX (via
  `core/code`'s import/export extraction), selected by a registry
  (`src/core/parsers/registry.ts`). Files dropped in `/files` or a project
  are parsed for real; unsupported/oversized files are rejected with
  `FILE_UNSUPPORTED`/`FILE_TOO_LARGE`, not silently accepted.
- **item 5 search/context/diff**: `core/search` (real inverted-index-style
  full text search + snippets), `core/context` (token-budget context
  assembly from real selected files + search results), `core/diff` (LCS
  line diff + context-collapsing) — all wired into `/files` search, the
  Project workspace's context-assembly for AI actions, and the "สร้าง
  patch" real edit/diff/apply flow.
- **item 6 `ai/providers` + `ai/router`**: `MockProvider` (no key needed,
  real streaming) and `GeminiProvider` (BYOK, real SSE streaming against
  the Generative Language API, mapped error codes) behind a shared
  `AIProvider` interface; `ai/router` picks the default provider/model from
  settings and falls back through the chain on failure when auto-routing
  is on. Chat, and the Project workspace's analyze/review/errors/fix
  actions, all go through this router — no more `setInterval` fake
  streaming.
- **item 7 error handling**: `types/errors.ts`'s `AppError`/`AppErrorCode`
  model is used end-to-end (storage, OPFS, parsers, providers, router) and
  surfaced in the UI with Thai messages instead of generic failures.
- **item 8 export/import**: `core/backup` builds a full JSON backup
  (conversations, projects, file metadata + base64 bytes, settings) —
  wired into Settings → "ส่งออกข้อมูล"/"นำเข้าข้อมูล".
- **item 9 tests**: `tests/core/*.test.ts` covers `core/diff`,
  `core/search`, `core/context`, `core/parsers` + `core/code`, and
  `core/storage` (CRUD via `fake-indexeddb`). Run with `npm test`.

All Phase 1 `MOCK_*` data and "ยังไม่ได้ตั้งค่า..." placeholder toasts have
been removed or replaced with real behavior (or an honest empty state that
links to where the user can actually configure the missing piece, e.g. "ไป
ตั้งค่า provider" when an AI action has no configured provider).

Known, intentionally out-of-scope gaps:
- Only one BYOK provider (Gemini) is implemented; the architecture doc
  mentions Cerebras as a possible future addition but it isn't in this
  registry.
- `core/parsers` handles text-based formats only (no binary/PDF/image
  parsing).
- The LCS diff is O(n·m); fine for single text files, not multi-megabyte
  binaries.

## Notable implementation choices beyond a literal 1:1 port

- `MarkdownMessage` was rebuilt on `react-markdown` (already named in the
  architecture doc's tech stack) instead of the prototype's
  `dangerouslySetInnerHTML` regex parser.
- The prototype's module-level `let idc = 1000` id counter was replaced
  with `crypto.randomUUID()` (`src/lib/id.ts`), since a module-level
  counter isn't safe once conversation/file ids need to survive route
  navigation and, later, persistence.
